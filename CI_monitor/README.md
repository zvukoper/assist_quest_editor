# CI Monitor

Плашка состояния проверок в строке состояния VS Code: номер последней
проверки, значок статуса и Windows-уведомление при смене результата.

Расширение работает в двух режимах, которые переключаются командой или настройкой
**`ciMonitor.mode`**:

| Режим | Источник данных |
|---|---|
| `github` | публичная страница `https://github.com/<владелец>/<репозиторий>/actions` |
| `local` | файл состояния локального прогона `.ci-state/local-run.json` |
| `auto` (по умолчанию) | локальный прогон, пока он идёт, затем GitHub |

GitHub API и токены не используются в обоих режимах, поэтому лимит обращений не
расходуется.

## Локальный режим

Локальный режим показывает прогон `ci/run_local.ps1` — тот же набор проверок, что
выполняет GitHub Actions, но без GitHub. Номер проверки и состояние задаёт скрипт,
поэтому плашка выглядит как обычная проверка, но с **числом пройденных проверок**.

Переключение происходит само: когда `pull.ps1` запускает проверки, он пишет файл
состояния, и расширение сразу переходит в локальный режим. После завершения
прогон удерживается ещё `ciMonitor.localHoldSeconds` секунд, а затем плашка
возвращается к GitHub — вручную ничего переключать не нужно.

```
🟩 $(check) 24/24 #2      прогон завершён успешно
⬛ $(sync~spin) 5/24 #99   проверки идут
🟥 $(x) 23/24 #100        проверки не пройдены
```

Прогресс показывается числом проверок (`пройдено/всего`), а не процентами:
по «45%» не видно, сколько проверок осталось, а по «5/24» — видно. Если общее
число неизвестно, прогресс не показывается — лучше пусто, чем выдуманное значение.

### Где хранится состояние

Два файла, оба вне `MemoryAI/LOGS`:

| Файл | Кто пишет | Зачем |
|---|---|---|
| `.ci-state/local-run.json` | `ci/run_local.ps1`, команда «Задать локальную проверку» | номер проверки, статус, прогресс |
| `.ci-state/monitor.heartbeat` | расширение, раз в секунду | признак активности редактора |

Каталог `.ci-state` выбран намеренно: `MemoryAI/LOGS` очищается после успешной
публикации, а номер проверки должен сохраняться между сборками. Иначе после
каждой успешной сборки нумерация начиналась бы заново с #1.

### Управление вручную

- **CI Monitor: Задать локальную проверку (номер и статус)** — задать номер и
  состояние (`queued` / `in_progress` / `success` / `failure` / `cancelled`).
- **CI Monitor: Режим Auto / GitHub / Локальный** — переключить режим.
- **CI Monitor: Скопировать путь к файлу состояния** — путь для ручного
  редактирования из терминала.
- **CI Monitor: Открыть отчёт проверок** — открыть `MemoryAI/LOGS/CI_errors.md`.

Файл состояния можно писать и вручную — формат совпадает с тем, что пишет скрипт:

```json
{
  "runNumber": 12,
  "status": "in_progress",
  "totalChecks": 11,
  "completedChecks": 5,
  "currentCheck": "Тесты домена",
  "failedChecks": [],
  "startedAt": "2026-09-21T09:41:08Z",
  "updatedAt": "2026-09-21T09:41:20Z",
  "branch": "main",
  "commit": "360a38e"
}
```

## Одно уведомление на прогон

При локальном прогоне уведомляет **расширение**, а штатное уведомление скрипта
не вызывается. Скрипт не может напрямую узнать о запущенном редакторе, поэтому
расширение раз в секунду пишет признак активности
`.ci-state/monitor.heartbeat`, а `pull.ps1` и `ci/run_local.ps1` проверяют
его свежесть (не старше 15 секунд).

Если редактор закрыт, признак устаревает и уведомление показывает сам скрипт —
иначе пользователь не узнал бы о падении проверок.

### Успех не уведомляется

При **успешных** проверках уведомление не показывается ни расширением, ни
скриптом: проверки прошли, значит приложение соберётся и запустится — этого
достаточно. Уведомление приходит только о проблемах:

| Итог прогона | Уведомление |
|---|---|
| проверки пройдены | нет (приложение собирается и запускается) |
| проверки не прошли | да, со списком упавших проверок |
| прогон отменён | да |

## Настройки

| Настройка | По умолчанию | Назначение |
|---|---|---|
| `ciMonitor.mode` | `auto` | `auto`, `github` или `local` |
| `ciMonitor.localHoldSeconds` | `20` | Сколько секунд держать завершённый локальный прогон в режиме `auto` |
| `ciMonitor.enabled` | `true` | Показывать плашку и опрашивать страницу |
| `ciMonitor.repository` | `""` | `владелец/имя`. Пусто — берётся из git remote проекта |
| `ciMonitor.branch` | `""` | Ветка для слежения. Пусто — текущая ветка git |
| `ciMonitor.refreshInterval` | `10` | Интервал опроса страницы в секундах (минимум 10) |
| `ciMonitor.showIdle` | `true` | Показывать плашку, когда проверок нет |
| `ciMonitor.badgeStyle` | `square` | `square` — цветной квадрат-подложка, `theme` — фон из темы |
| `ciMonitor.notifications` | `windows` | `off`, `windows`, `vscode`, `both` |
| `ciMonitor.notifyOnStatuses` | `["failure","success"]` | О каких состояниях уведомлять |
| `ciMonitor.notifyOnStartup` | `false` | Уведомлять о состоянии на момент запуска редактора |
| `ciMonitor.requestTimeout` | `15000` | Таймаут запроса страницы, мс |
| `ciMonitor.logLevel` | `info` | `silent`, `error`, `info`, `debug` |

## Команды

- **CI Monitor: Open Actions Page** — открыть страницу Actions (в локальном режиме — отчёт).
- **CI Monitor: Open Latest Run** — открыть последний запуск (в локальном режиме — отчёт).
- **CI Monitor: Режим Auto / GitHub / Локальный** — переключение режима.
- **CI Monitor: Задать локальную проверку** — номер и статус локального прогона.
- **CI Monitor: Открыть отчёт проверок** — `MemoryAI/LOGS/CI_errors.md`.
- **CI Monitor: Скопировать путь к файлу состояния** — путь к `.ci-state/local-run.json`.
- **CI Monitor: Refresh Now** — опросить страницу немедленно.
- **CI Monitor: Test Windows Notification** — показать пробное уведомление.
- **CI Monitor: Show Log** — открыть журнал расширения.
- **CI Monitor: Open Settings** — открыть настройки расширения.

## Ограничение оформления

Статус-бар VS Code допускает для `StatusBarItem.backgroundColor` только две
темы: `statusBarItem.errorBackground` (красный) и
`statusBarItem.warningBackground` (жёлтый). Произвольный цвет фона платформа
отбрасывает (`ALLOWED_BACKGROUND_COLORS` в `extHostStatusBar.ts`).

Управляющие последовательности ANSI тоже не работают: текст пункта строки
состояния вставляется обычным текстовым узлом (`renderLabelWithIcons` создаёт
только `<span>` с codicon), поэтому ESC-коды видны как мусор. Это проверяется
скриптом `tests/ansi-probe.mjs`.

Поэтому цветные состояния по умолчанию показаны квадратом-подложкой
(`ciMonitor.badgeStyle = "square"`), а режим `theme` использует красный и жёлтый
фон из темы там, где платформа их поддерживает.

## Зависимости

- **Node.js 18+** — используется встроенный `fetch` для загрузки страницы.
- **Windows 10/11** — для уведомлений Windows (через WinRT-классы
  `Windows.UI.Notifications`, без сторонних модулей и прав администратора).
- Редактор **VS Code 1.85+**.

На других платформах расширение работает, но уведомления Windows недоступны:
при `ciMonitor.notifications = "windows"` сбой доставки приводит к показу
уведомления средствами редактора.
